# 渐进总览验证

## 实现
- 分支：`fix/progressive-overview`，基线 `cf5560930cc7de19b0e74174867610fef32038ff`。
- 总览、线程、任务内容请求超时为 60,000ms。活动观测仍保持独立 6 秒超时。
- `/api/snapshot` 无参数保留全量兼容行为；UI 使用 `?progressive=1` 获取项目元数据与冻结工作列表，再依 `?cursor=...` 读取真正的服务端增量批次。
- `progress.delta=true`；每页最多 8 个线程，100ms 软预算。项目轮转扫描，前端按最新活动全局排序，不让第一个大项目阻挡其他项目首批数据。
- 最多 2 个并发扫描请求、4 个扫描会话，120 秒闲置过期。只缓存最近一页用于幂等重放；旧 cursor 返回 410，并发忙返回 503。无活动请求共享扫描锁。
- 前端为本轮累加增量与身份/统计；部分读取期间覆盖旧记录但不据缺失删除，成功完成后才替换旧代。路由读取独立启动；新默认身份到达时会加载对应任务。暂停、替换请求和过期响应受代号保护。
- 首批真实记录立即绘制；快速后续页面最多约每100ms重绘一次，并有尾沿定时器，后续网络请求卡住不影响已收到数据展示。

## 验证结果
- 独立审阅通过；发现并修复：默认任务身份重排后的漏读、累积服务端重聚合性能回退、节流缺少尾沿绘制。
- 生产 app.js 的 Node DOM 测试：慢响应 6.36s 接受，59.999s 不提前终止，60s 准时终止；覆盖总览、线程和任务。按批次重新计时。
- 实际服务端增量载荷送入生产前端，最终输出与旧全量 snapshot 一致，包含待处理数、最近12条、协作者统计。
- 覆盖117线程跨项目排序、12项目/120线程首批、cursor重放/过期/资源上限、活动HTTP不被慢扫描阻挡、部分错误/重试/删除、隐藏/导航/旧响应、滚动锚点/展开/筛选/输入焦点。
- 合成计时（非用户私有数据）：12项目/120线程首批0.011s、完整0.209s；18线程注入慢读首批0.108s、完整0.487s。
- 1000线程无I/O结构测试：每页和重放缓存始终≤8条，会话不保留累积记录；最终本地0.088s增量/0.094s旧全量，独立复核0.172s/0.146s。计时随机器负载变化，不作为脆弱的固定性能断言。
- 最终冻结全套回归：248项通过（81.538s），命令 `python -m unittest discover -s tests -v`；包括原有229项及新增19项。
- `git diff --check`、`node --check ui/app.js`、`python -m py_compile scripts/ui_server.py` 通过。

## 未验证与边界
- 实际 Chromium 测试启动失败：`socket() failed: Operation not permitted`，进程 SIGABRT（另有 crashpad 数据库错误）。未绕过权限，未声称真实浏览器通过。
- 未访问用户本机数据、私人聊天或被禁止的 session 目录。合成计时不保证用户机器上的同等耗时。
- 初始项目/线程目录枚举仍需完成；100ms 为软预算，单个慢文件系统/线程读取不可强行中断。前端60秒终止等待不杀死正在执行的一次后端扫描；最多2个扫描槽限制并发。
- 实施验证结束时未 commit/push；旧工作树保持干净。2026-11-02 用户随后明确授权本批直接发布 main，见 spec.md D3。发布前远端复核仍为上述基线；使用非强制更新及 expected_sha 保护并发改动。

# 触发式增量读取验证

## 根因
旧 `CONTENT_POLL_MS=3000` 配合 `load()` 完成后的 `scheduleContent()`，会在一次分批扫描结束3秒后重新扫描全部线程。此前分批只分割单次读取，没有跨刷新版本复用；标签页恢复也自动重启内容读取。

## 修复
- 内容只在首次加载、页面导航、明确刷新时请求；无周期内容定时器。渲染、筛选、展开、滚动、标签页恢复不启动内容请求。独立2秒运行活动心跳仍维持真实、未过期的工作动画，不启动 snapshot。
- 并发导航共享当前扫描，详情请求去重；新变更集会使相关旧请求失效，迟到响应不能清除新失效标记。
- `progressive=1&since=<completed-version>` 对比安全文件元数据指纹，只投影新增/变化线程。包括回合、通知、已读状态、身份绑定、wake配置、本地人类输入、任务证据、源代码及Git成员/嵌套工作树变化。
- 指纹只读取元数据，支持合法仓库内symlink目标并限制循环；外部symlink目标不会访问。不读取未变化线程的正文进行指纹比较。成功完成才发布新版本并对账删除；中途错误、元数据变化、过期cursor不推进已完成基线。
- `sync.reset` 明确报告版本失效；完整浏览器重载丢失内存基线时走初始读取。旧全量snapshot及旧分批响应保持兼容。
- 保留每请求60秒、每页最多8线程、全局活动排序、滚动/展开/输入焦点、原始人类输入隐私限制。

## 验证
- 独立审阅通过：17项后端增量测试、9项前端触发测试通过，无剩余必须修复项。
- 生产app.js请求计数验证：加载完成后计时器不重启内容读取；渲染/筛选/展开/标签页恢复零内容请求；导航/刷新复用版本与未变详情。
- 合成127线程最终计时：首次0.895s/127次线程投影；未变化刷新0.2573s/0次线程投影、1个响应。计时不是用户机器保证。
- 实际后端两代增量载荷送入生产前端，修改/新增/删除后与完整snapshot一致；无变化刷新调用 `scan_thread` 为0。
- 覆盖旧响应竞争、失败后重试、丢失/过期版本、缓存数量/字节限制、源代码与Git索引变化、扫描期间身份/wake变化、symlink安全及超容量不自动重试。
- 最终冻结全套274项通过（114.303s）：`python -m unittest discover -s tests -v`；包含原有248项及新增26项。
- `node --check ui/app.js`、`python -m py_compile scripts/ui_server.py`、`git diff --check` 通过。

## 边界与发布状态
- 每次授权触发仍枚举必要文件元数据；增量避免未变化正文解析/线程投影，不承诺完全不访问文件系统。
- 完成版本：最多4个，闲置15分钟；单代投影32MiB、总完成缓存64MiB。超过单代容量明确返回413并保留旧基线，不自行循环重试。活跃分批仍最多2个并发扫描/4个会话/120秒闲置过期。
- 浏览器真实图形QA本轮未运行：此前同执行环境Chromium启动已因 `socket() failed: Operation not permitted` 失败，无新的权限证据，未重试或绕过。DOM测试不等同真实浏览器或用户机器验证。
- 未读取用户私有会话，未集成自动任务功能。验证结束时未commit/push；用户随后明确授权本批直接发布main，见spec.md D4。分支 `fix/triggered-incremental-refresh`，基线 `b5816a926694ae2e80be7059e3c809f6a3147971`。
- 更新部署时需重启已运行的UI服务并刷新浏览器，让服务端与前端同时使用新代码；本轮未操作用户服务。

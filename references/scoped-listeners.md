# 协作者默认怎么监听

开始等待协作消息时，只选择当前成员确实需要等待的对方，不默认监控所有线程和成员。按该名单和最近上报的客户端选择：

- 当前是 Cursor、Claude Code 或其他非 Codex 客户端：如果名单非空，由自己的已打开会话开启监听，默认每 **5 分钟**查一次。
- 当前是 Codex，对方全是 Codex：**不启动监听**，走发布后的会话直发提醒。目标须有唯一有效的会话绑定；没有绑定或绑定不唯一时明确指出缺口。发送结果未知时不盲重发。
- 当前是 Codex，名单里有其他客户端：Codex 协作者自己**不得创建监听**。把非直发对象登记到这个 Codex 实例已有的**共享 Luna 转发会话**，默认每 **2 分钟**查一次。Codex 对象继续直发。
- 对方没上报或已过期时不能当成 Codex：列为未知并暂纳入监听范围，复核后再改。当前客户端用当前会话的真实工具，不用成员名字猜。

## 一个实例一个转发会话

同一 Codex 主机与当前账号配置共享一个 Luna 转发会话，不按项目、线程或收件人新建。开始前先查找已有会话，复用其调度。每条登记以「项目绝对路径、线程、收件人」去重，记录需要监听的发送人、自定义间隔、最近一次发现新消息的时间和最后处理的消息 ID；同一个转发循环仅扫描到期的登记。不同主机或账号配置不能共享会话。不能使用 Luna 或本机调度能力缺失时，报告缺口，不给各 Codex 协作者分开开监听，不替换成更贵模型。

转发只向该登记收件人唯一绑定的已有 Codex 会话发送提示，包含项目、线程、回合和消息 ID。转发器不冒充协作者发布或确认协作信号，不处理任务正文。依据项目、线程、收件人及消息 ID 去重；可能已送达的请求不重发。直接发布已负责通知的 Codex 对象无需再经转发。不得读取未登记的项目或向其他会话转发。

## 停止和自定义

- 协作确认完成、线程关闭/取消或用户要求停止时，停止对应监听。明确的关闭消息如尚未通知，先转发再移除登记。
- 关注范围连续 **60 分钟**无新消息后主动停止，从开启或最后一次发现新消息起算。重复、无效或同一条待处理消息不续期。
- 只停止完成或到期的登记。共享转发器没有任何登记时才停其调度；保留会话可供下一次复用。不要创建自重启循环。
- 用户可按订阅调整普通间隔、转发间隔和空闲时限。原有无人值守执行流程和已有会话不因更新技能而被改变。

## 给已具备调度能力的客户端

```bash
python scripts/collab.py listener-plan --root . --thread-id example --agent reviewer --client codex --peer builder --peer verifier
```

返回 `mode`、直发和待监听成员、有效间隔与空闲时限。可覆盖 `--interval 5 --relay-interval 2 --idle 60`。轮询扫描时传 `--started-at`，以 ISO 时间传递，并将上轮结果的 `last_new_at` 和 `seen_message_id` 传回。明确确认完成时加 `--completed`；收到 `stop` 时停，收到 `stop_after_delivery` 时先通知最后一条再停。检查双方客户端状态及转发范围，不把这条命令本身当作调度器。宿主负责登记、选择 Luna 模型、定时调用、投递及真正停止；没有挂上调度之前不宣称监听已经运行。

# 在线程窗口给协作者发反馈

在线程底部输入 `@` 并选择协作者，也可直接输入 `@协作者 消息`。Enter 发送，Shift+Enter 换行。沿用本机 WebUI 授权；纯只读服务没有发送 API。

- **已明确绑定 Codex 的成员**：反馈进入绑定的会话队列。按[手动接入](manual-session-ingress.md)绑定会话 UUID。服务与目标会话使用同一个 Codex 数据目录，不使用 resume。已入队不表示已读。
- **其他线程成员（含 Cursor、Claude Code）**：反馈放进项目本地私有收件箱。已开启监听的会话在原项目、用该成员身份继续轮询 `python scripts/collab.py inbox --root . --agent <成员> --format json`，或 `--format text`。看到 `FEEDBACK` 时读取正文，处理后运行 `python scripts/collab.py feedback-ack --root . --agent <成员> --thread-id <线程> --message-id <编号>`。接收无需绑定工具或会话 ID，等到下次轮询才会读到。只打开聊天而未轮询不会收到。CLI 唤醒脚本、watch、prompt 格式不处理该项。

反馈不是正式回合、验收记录或自动任务批准。不写 Git 共享记录，不改原信号。监听反馈待确认的正文保存在项目的本地私有数据库，确认后去除正文，留下幂等记录。尝试结果不明时不会自动重发；使用原请求编号重试不会重复投递。

当前客户端由已运行的监听会话在 JSON/text 轮询时加 `--client cursor`、`--client claude-code`、`--client codex` 等上报；也可在该监听进程设置 `COLLAB_CLIENT`。按项目和成员保存最近一次，上报即更新，15 分钟无上报显示「客户端未知」。再次输入 `@` 会重新读取近期状态。切换时停止旧会话监听，两个会话同时上报时以后到的为准。「客户端未知」表示近期上报过期，不会清空上次明确选择的投递客户端；切换时请在新客户端上报，且不自动改变既有的精确会话绑定。

正式协作回合通过 `collab.py publish` 发布后，若双方最后明确上报的客户端均为 Codex，且收件人在本线程有且仅有一个有效的 Codex 会话绑定，会向该已有会话入队一条提醒。提醒只含线程、回合、发送人和消息 ID，正文仍从协作记录读取。会话未绑定或绑定有歧义时不猜测；通知失败也不影响发布，同一消息已尝试后不盲目重发。
